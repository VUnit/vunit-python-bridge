## Changes

- `import_module_from_file` resolves a relative path against the directory of the testbench file, like `exec_file`, rather than against the working directory of the simulator. It must be called after `test_runner_setup`. Callers that relied on a path relative to the working directory must pass an absolute path instead. See #7.
- A relative file name of `exec_file` or `import_module_from_file` used before `test_runner_setup` has completed, or without a test runner, is reported as a failure. It was taken from the working directory of the simulator, which gave a misleading file-not-found error. A verification component can instead load its files with `join(base_path, ...)`, where `base_path` returns a directory set by `vunit_python_bridge.set_relative_file_base()` in the run script or by the environment variable `VUNIT_PYTHON_BRIDGE_FILE_BASE`, which takes precedence, for example `VUNIT_PYTHON_BRIDGE_FILE_BASE=$(CURDIR) python sub/run.py` in a Makefile. This works at any time. A verification component can also wait for `test_runner_setup` as the user guide shows.
